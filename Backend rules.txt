## 1. PROJECT VISION

"Mecano" is a full-stack web platform for managing bookings and service appointments at an automotive workshop. It allows staff to select clients, view availability on an interactive calendar (FullCalendar), register vehicles, filter mechanics by specialty, and schedule appointments while preventing time overlaps.

---

## 2. NON-NEGOTIABLE PRINCIPLES & REQUIREMENTS

### A. Architecture & Technology Stack
1. **Framework:** Blazor Server on .NET (C#, HTML5, CSS3, Bootstrap 5).
2. **Visual logic & interop:** `FullCalendar` via JS Interop (or a native Blazor wrapper) for graphical display of appointments and free slots.
3. **Persistence:** Relational database (MySQL / PostgreSQL) via Entity Framework Core.
4. **Blazor Server concurrency:** MUST use the `IDbContextFactory<MyDbContext>` pattern with short-lived contexts (`using var ctx = await _factory.CreateDbContextAsync();`) to avoid concurrent-thread errors.

### B. Code & Engineering Principles (SOLID / OOP)
1. **SOLID & Clean Code:** Strict application of SRP and DIP. Also apply OCP, LSP, and ISP where relevant. DRY, KISS, YAGNI, Law of Demeter, composition over inheritance.
2. **Domain design:** Encapsulation in entity models, server-side validation (Fail-Fast), explicit exception handling, and no anemic models.
3. **Dependency injection:** All business-logic services MUST be injected via interfaces (`IClienteService`, `ICitaService`, `IMecanicoService`, `IVehiculoService`, `IServicioService`, `ICategoriaService`). Concrete implementations are resolved by DI.
4. **Testing:** Behavior-focused unit tests. Fakes over mocks where possible. Deterministic, readable tests for the overlap rule and availability filter.
5. **Observability:** Explicit error handling; no swallowed exceptions; meaningful domain exceptions (e.g., `AppointmentOverlapException`, `InactiveMechanicException`).

## 4. FUNCTIONAL FLOW — CORE SCHEDULING SCREEN

Implement the interactive scheduling view (`AgendarCita.razor`) following this 6-step flow strictly:

### Step 1 — Customer Selection
- User searches and selects a person "X" by name, ID, or license plate using a dynamic search box.
- Results are paged and debounced; selection returns a `ClienteId`.

### Step 2 — FullCalendar Visualization
- The `FullCalendar` component is rendered.
- Shows occupied time blocks and free slots for the workshop.
- Data source is an `ICalendarQueryService` (new interface) returning events for the visible date range only.

### Step 3 — Time Slot Selection
- Clicking a free slot/day-time in `FullCalendar` captures the selected `Fecha` and `HoraInicio`.

### Step 4 — Confirmation & Registration Modal
- A Bootstrap modal opens automatically.
- **Auto-load:** Shows the selected customer's info and lists their registered vehicles in a `<select>`.
- **Quick vehicle registration:** Includes a "➕ Add new vehicle" tab/option inside the same modal (Plate, Make, Model, Year) to attach it to the customer immediately if none existed.

### Step 5 — Service Selection & Smart Mechanic Filter
- When the **Service Type** is selected:
  1. The system computes `HoraFin` from the service's `DuracionMinutos`.
  2. **Specialty filter:** Keeps only mechanics whose `EspecialidadId` matches the service's category.
  3. **Temporal availability filter:** Validates that the mechanic has no other appointment overlapping `[HoraInicio, HoraFin)` in the database for that date.
  4. **Active filter:** Only mechanics where `EstaActivo == true`.
  5. Returns only qualified AND free mechanics for that time block.

### Step 6 — Booking Confirmation
- User confirms in the modal.
- The booking is persisted, `FullCalendar` refreshes in real time showing the new occupied block, and a simulated email-notification is displayed.
- Overlap must be enforced at two layers: (a) application-service check, and (b) a DB unique constraint or transactional guard to prevent race conditions.

## 5. SERVICE CONTRACTS (REQUIRED INTERFACES)

Define at minimum:
- `IClienteService` — search, get by id, register.
- `IVehiculoService` — list by customer, register.
- `IServicioService` — list, get by id, compute `HoraFin`.
- `IMecanicoService` — list by specialty, list available in time range.
- `ICitaService` — create appointment (with overlap rule), cancel, list by range.
- `ICalendarQueryService` — events for FullCalendar visible range.
- `INotificationService` — simulated email notification.

Each interface must have a single, cohesive responsibility. No "manager" god-interfaces.
